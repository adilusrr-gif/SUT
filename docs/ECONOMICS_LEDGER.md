# Журнал фактической экономики

1. В новой базе задайте DEMO_SEED=false до первого запуска. Если DEMO уже создан, переключение флага его не удаляет: используйте отдельную пилотную базу или согласованную миграцию данных.
2. Войдите по коду доступа из .env. Создайте ферму и первую группу. Начальные ограничения питания — шаблон, их нужно проверить с зоотехником до использования оптимизатора.
3. На «Обзоре» выберите группу и день. Введите число коров, суммарную стоимость израсходованного корма, выручку за молоко этого дня, прочие расходы и источник. Суммы относятся ко всей группе, не к одной корове. Не смешивайте начисленную выручку за день с поступлением оплаты за прошлый месяц. Одинаковая методика нужна в обоих периодах.
4. При исправлении выберите день, дождитесь загрузки, внесите значения и причину. Старая версия остаётся в истории. При409 обновите журнал и повторно сверяйте значения; чужое изменение не будет молча перезаписано.
5. Выберите окончание периода ПОСЛЕ и 7 либо30 дней. Период ДО имеет ту же календарную длину и предшествует ему. API поддерживает произвольные непересекающиеся последовательные периоды в диапазоне731 дня.

Корово-дни = сумма ежедневного числа участвующих коров. Суммы таблицы — фактически введённые итоги. Для сравнения:

- k = корово-дни ПОСЛЕ / корово-дни ДО;
- экономия корма = корм ДО × k − корм ПОСЛЕ;
- изменение выручки = выручка ПОСЛЕ − выручка ДО × k;
- изменение маржи над кормом = экономия + изменение выручки;
- после прочих введённых расходов = изменение маржи − (прочие ПОСЛЕ − прочие ДО × k).

Каждый показатель округляется до0,01 ₸ в конце расчёта; из-за округления сумма показанных компонентов может отличаться на0,01 ₸. Отрицательные значения сохраняются. Без данных одного периода эффект отсутствует, а не равен нулю. Неполные периоды показывают охват; не внесённые дни нельзя считать бесплатным кормлением. Сравнение разного числа/состава коров не устраняет различия лактации, сезона и здоровья.

Это сравнительный эффект по ручному вводу, не причинная оценка работы алгоритма и не чистая прибыль. Другие затраты учитываются только в объёме ввода. Источники — текстовые ссылки/описания; прикрепления документов и автоматической сверки пока нет. Приложение не проверяет достоверность введённых сумм.

API (тот же Bearer-код доступа):
- POST /api/economics/{group_id}/entries — day, cow_count, feed_cost_kzt, milk_revenue_kzt, other_cost_kzt, source, correction_reason, expected_revision, request_id(UUID).
- GET /api/economics/{group_id}/entries?start=YYYY-MM-DD&end=YYYY-MM-DD — актуальные версии.
- GET /api/economics/{group_id}/history/{day} — все ревизии дня.
- POST /api/economics/{group_id}/compare — before_start, before_end, after_start, after_end.

Новая запись: expected_revision=0. Исправление: номер последней revision и непустая причина. Повторяйте тот же request_id только с идентичным телом; для нового намеренного исправления нужен новый UUID. Денежные значения отправляйте десятичными строками. Будущие дни относительно серверной даты отклоняются. Настройка часового пояса фермы пока отсутствует; у сервера и оператора может различаться календарная дата возле полуночи.

Журнал сохраняет историю через API добавлением записей; это не криптографически неизменяемое хранилище. Администратор БД может изменить данные. Общий код доступа не определяет персонального автора: перед несколькими независимыми пользователями нужны учётные записи и роли.
