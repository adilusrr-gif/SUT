# Поставка Süt v2.3.0

Выполнено: дневной журнал денежных данных по группам, история исправлений, защита от дублей и устаревших исправлений, сравнение периодов на одинаковую базу корово-дней, UI 7/30 дней, создание первой фермы и группы без DEMO. Существующие рационы, OpenAI/Ollama и оптимизатор сохранены.

Проверено локально: 42 pytest теста на SQLite, включая13 новых сценариев финансового журнала и первого запуска. TypeScript и Vite production build успешны. Тесты проверяют отсутствие двойного счёта, отрицательный эффект, пропуски, неизменность прошлого при редактировании текущих цен/поголовья, ревизии и повторную отправку. Артефакты: verification-v2.3/tests.txt, junit.xml, build.txt.

Ограничения: Docker и PostgreSQL здесь недоступны; PostgreSQL-конкурентность, резервное восстановление и обновление реального сервера не проверены. Playwright-библиотека есть, но исполняемый Chromium отсутствует; браузерный сценарий не пройден. Внешние модели проверяются имитацией. На сервере192.168.1.18 ничего не развёрнуто. Полного повторного Project Sentinel-аудита v2.3 не было; audit/ относится к предыдущей v2.2.

Деньги в журнале — ручные суммы со ссылкой/описанием источника; автоматическая проверка документов отсутствует. Фактическая экономия хозяйства и причинный эффект изменения рациона ещё не измерены. Не называть сравнительный эффект гарантированным заработком.

Перед пилотом на сервере:
1. Сделать резервную копию существующей базы и проверить восстановление в отдельную базу.
2. Сохранить существующий .env и пароль БД; добавить отсутствующие переменные, не заменять секреты шаблонами.
3. Выполнить docker compose up -d --build; проверить docker compose ps и логи backend.
4. Открыть приложение через SSH-туннель: ssh -L 8088:127.0.0.1:8088 ai@192.168.1.18, затем http://127.0.0.1:8088 на своём компьютере.
5. На отдельной тестовой группе внести два дня, исправить один и проверить историю и итоговые суммы. Повторить в двух окнах с устаревшей версией: второй конфликт должен дать409.
6. Подтвердить профиль питания и правила учёта затрат со специалистами фермы, затем начать сбор baseline.

Не запускать docker compose down -v: это удаляет том базы. Проверки этого окружения не заменяют серверную приёмку.
