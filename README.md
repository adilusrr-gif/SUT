# Süt • Рацион — 2.1.0, OpenAI

Исходники полной самостоятельной версии приложения: React + FastAPI + PostgreSQL + LP-оптимизатор. Основа — SUT_Ration_v2_Release от 12 сентября. Этот архив продолжает ветку v2; он не заменяет опубликованный Sites автоматически и не является прежним stateless-пакетом sut-server-docker.

## Что изменилось

- Добавлен OpenAI Responses API со строгой JSON-схемой ответа.
- Провайдер переключается настройкой: openai / ollama / disabled.
- Все бизнес-API требуют код доступа APP_ACCESS_TOKEN; он отличается от OPENAI_API_KEY.
- Модель выбирает только акцент объяснения. Суммы и количества подставляет код из сохранённого расчёта.
- Кэш успешных объяснений в PostgreSQL; ключ включает данные расчёта, модель, провайдера и версию инструкции.
- Дневной лимит попыток LLM в базе; не сбрасывается при перезапуске приложения. Счётчик атомарный для нескольких процессов.
- Ошибки 401/429/5xx, таймаут, отказ, неполный или неверный ответ → шаблонное пояснение.
- По умолчанию Compose не запускает Ollama и не требует GPU.

## Первый запуск на Ubuntu

Распакуйте в новую директорию. Требуются Docker Engine, Compose v2 и Python 3. На Windows после скачивания:

```powershell
scp .\SUT_Ration_v2_Release.zip ai@192.168.1.18:~/
ssh ai@192.168.1.18
```

На сервере:

```bash
python3 -m zipfile -e ~/SUT_Ration_v2_Release.zip ~/sut-release-2.1
cd ~/sut-release-2.1/sut-v2-release
python3 deploy/init_env.py
nano .env
```

Настройте:

```dotenv
LLM_PROVIDER=openai
OPENAI_API_KEY=ваш_ключ_на_сервере
OPENAI_MODEL=gpt-4o-mini
LLM_TIMEOUT_SECONDS=20
LLM_MAX_OUTPUT_TOKENS=128
LLM_DAILY_CALL_LIMIT=100
```

Модель приведена как пример совместимой конфигурации; доступность в вашем API-проекте проверяется реальным вызовом. Можно указать другую доступную модель с поддержкой Responses и Structured Outputs. Модель со скрытыми reasoning-токенами может исчерпать маленький лимит вывода; тогда пояснение будет шаблонным. Не увеличивайте лимит без оценки расхода.

Пароль PostgreSQL и APP_ACCESS_TOKEN уже сгенерированы скриптом. Сохраните код APP_ACCESS_TOKEN для входа в интерфейс. **OPENAI_API_KEY вводится только в .env на сервере**, не в интерфейсе и не в чате.

```bash
docker compose up -d --build
docker compose ps
curl -fsS http://127.0.0.1:8088/api/health
```

Адрес слушает только localhost сервера. Для просмотра с Windows откройте второй PowerShell:

```powershell
ssh -N -L 8089:127.0.0.1:8088 ai@192.168.1.18
```

Откройте `http://127.0.0.1:8089` и введите APP_ACCESS_TOKEN. Код хранится в памяти вкладки, после обновления страницы нужно войти снова. Это общий доступ одной пилотной фермы, не многопользовательская система с ролями.

Для внешнего пилота потребуется защищённый HTTPS-шлюз/туннель. Он пока не настроен. Проверить, свободен ли серверный порт 8088, нужно перед запуском. Другие приложения, Ollama и их порты пакет не меняет.

## Проверка OpenAI

1. Войти в приложение.
2. Выполнить оптимизацию на учебных данных.
3. Открыть «ИИ-пояснение» и нажать «Объяснить расчёт».
4. При успешном обращении интерфейс показывает провайдера/модель; статус настроек сам по себе **не доказывает** доступность API.
5. Нажать снова: успешное сохранённое пояснение должно вернуться из кэша без новой оплаты.

Лимит 100 — максимум попыток за сутки UTC, а не $100 и не обещание конкретной стоимости. Ограничение включает неудачные запросы. Автоматических повторов нет. Одновременные первые запросы одного расчёта могут оба обратиться к модели до заполнения кэша, но дневную квоту не превышают.

Фактические input/output/total tokens успешного запроса возвращаются в `usage` и сохраняются с пояснением. При ошибке данные о расходе могут быть недоступны. Стоимость сверяется в биллинге провайдера.

Внешней модели передаются только число изменений и два признака: положительна ли экономия и есть ли предупреждения. Названия фермы/кормов, персональные данные, полный рацион и суммы не отправляются. `store=false` отключает сохранение объекта Responses для последующего получения, но не означает обещание нулевого хранения всех данных провайдером.

## Ollama и работа без ИИ

Чтобы использовать отдельную Ollama из этого Compose:

```dotenv
LLM_PROVIDER=ollama
OLLAMA_URL=http://ollama:11434
OLLAMA_MODEL=deepseek-r1:14b
```

```bash
docker compose --profile local-ai up -d --build
docker compose exec ollama ollama pull deepseek-r1:14b
```

Этот дополнительный контейнер требует GPU-настройки Docker и может конфликтовать с уже занятым портом 11434. **Для существующей Ollama пользователя не запускайте профиль local-ai вслепую**: задайте достижимый из backend-контейнера адрес после проверки сети. `127.0.0.1` внутри backend-контейнера не является localhost хоста.

Без сетевых запросов к модели:

```dotenv
LLM_PROVIDER=disabled
```

После изменения настроек:

```bash
docker compose up -d --force-recreate backend
```

## Обновление существующего v2

1. Сделать резервную копию базы (`deploy/backup.sh`) и сохранить прежний код.
2. Сохранить исходные POSTGRES_* и имя Compose-проекта/тома. Новая директория с другим именем проекта иначе создаст другую пустую базу. Не запускать `down -v`.
3. Добавить APP_ACCESS_TOKEN, LLM_PROVIDER и OPENAI_* в существующий .env. Скрипт init_env не перезаписывает существующий файл. Код доступа можно создать командой `python3 -c "import secrets; print(secrets.token_urlsafe(36))"` локально на сервере.
4. При старте добавятся таблицы `ai_explanations` и `ai_daily_usage`; старые таблицы и данные не удаляются. Здесь используется унаследованный create_all, полноценная система миграций ещё не внедрена.
5. Запустить сборку, проверить вход, расчёт и пояснение. Реальная миграция PostgreSQL в среде подготовки не проверялась.

## Ограничения

Это версия для технической проверки, не подтверждённый production-релиз. Docker/PostgreSQL, реальный OpenAI и браузерный сценарий на вашем сервере ещё не проверены. Нет ролей пользователей и разделения нескольких хозяйств. Не выполнен полный аудит безопасности и биологической модели.

Сохраняются ограничения v2: редактируемые цены без полноценной истории партий; для старых предложений ещё нет защиты от применения после изменения исходных данных. Формулы используют float. Дашборд показывает потенциал экономии и маржу над кормом, а не доказанную фактическую прибыль. Нормы питания и внедрение подтверждает специалист.

Следующий этап: запуск на сервере; затем неизменяемые снимки цен/анализов и защита устаревших рекомендаций, фактическая выдача и остатки корма, проверяемое сравнение ДО/ПОСЛЕ. Эти функции не выдаются за реализованные в 2.1.

Документация реализации OpenAI: https://developers.openai.com/api/docs/guides/structured-outputs
